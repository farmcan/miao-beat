## 第一步：并行定位，停止盲调（执行中）

**A / 眼部 builder**：同一冻结 C14C、相机、灯光、曝光，实际比较原角膜、仅 IOR=1、仅隐藏角膜三组。隐藏仅用于因果诊断，不是交付。输出完整帧、头特写、源文件SHA、变更检查与结论。最多这三项；确定下一项最小试验后再改材质，禁止成批扫参数。

**B / 手爪 builder**：读取 C16 正侧/inside、实际截面和原图，提出一个从前臂到掌根再到三趾的共享控制笼。先给轴向、掌根朝向、保留/重建区域和两张灰模试验设计；不再把两个闭合体加连接杆或不断调 smooth-min。根因尚属推断，需要反事实验证。

**C / root**：固定 Godot 当前迁移证据，记录毛、眼、灯、木纹、体积损失和可复现命令；整理阶段状态与源文件。暂不在未合格模型上加 IK / 随机动作掩盖问题。

**独立评审池**：身份/轮廓/表情、材质/工艺/灯光、动作/接触/体验三个角色。builder 不评自己的产物；按并发槽空闲安排评审，最多3个子agent同时运行，不要求每个角色同时常驻。

## 第二步：只修明确的静态阻塞

1. 按眼部诊断结论做一个最小修复，保留眼白、虹膜、角膜间完整关系和向右视线；同镜头确认整身与近景，不以藏掉高光/眼睛冒充修好。
2. 共享控制笼先验证前臂—掌根连续体积；若两张灰模仍读作圆垫/套环，停止该候选，记录反例并换结构。通过后才恢复三趾、掌背软褶及真实抱琴接触。
3. 单独重建拨弦爪，保留短掌、短圆指尖和松弛握姿。不能只修按弦爪后宣布双手完成。
4. 合并头、双爪、身体与琴，做同机位整身/脸/双手/侧面灰模三评。拓扑替换后，旧 UV、毛根、shape key 和绑定证明全部失效，重新制作或验证。
5. 再修耳壳软边、嵌入式虎斑、短绒与光照；彩色三评通过后固定新的唯一资产版本。任何 P0 回到对应部位，不用综合分放行。

每个候选上限两次有明确目的的修订。达到上限仍失败则保留文件并换方法，不无限累积同类试验编号。数字审计用于发现问题，不能替代实际看图。

## 第三步：动画先做一个真实核心动作

先用完整连接角色完成：右爪离弦 → 一次跨弦接触 → 回到可再次弹奏的位置；左爪保持琴颈承托，琴和肩不过度漂移。先交原速与慢放短片、接触特写、时间线和源文件；三名独立评审实际看片。

通过后接真实输入：单按只有一次主要接触；按住不自动补演；500 ms 慢连按每次可辨；150 ms 快连按右爪持续可见且不卡在休止位；停止后不继续补演排队动作。离弦和回程允许按速度缩短，不把整段静态抱琴重播当弹奏。

最后加入独立时钟的眨眼、微视线、小幅头部跟随、呼吸和低频耳动。手部约束优先；快音不逐音重置头部；随机有固定seed、开关和幅度界限。真实闭眼覆盖全部可见眼部光学表面，不缩放眼球假装眨眼。

## 第四步：同资产比较两个引擎

- **Blender A**：保留原生短绒/材质/灯光，输出完整帧视频，再接网页按键播放器和音画录制。
- **Godot B**：先解决减面、木纹烘焙、眼部与毛的保真，再接原生动画层/受约束 IK。每次跨引擎导入先看同相机完整帧，不带着材质损失直接扩动作。

两版使用同角色版本、构图、输入事件和随机seed，比较实际图像、接触、时延、文件体积与设备实测性能。未测 FPS、手机/Web 或音画输出就标未验；不能拿加载加45帧的总时间充当性能结果。

## 第五步：最终验收与交付

交付包含 A/B 原速/慢放实片、原图并排、原生工程、输入事件、来源许可、运行与复现文档、剩余缺口。每帧都是完整相连的猫、双爪和琴，不使用身体底图叠独立手臂。

独立动作 judge 必须看片，并检查单按/按住/慢连/快连/停止和随机动作组合；还需真实浏览器点击/键盘 → 音画响应 → 回放 → 导出含角色视频与音频的闭环。工程可运行不能替代这些验收。

源代码与文档采用已授权 commit/push；避免提交凭据、缓存与无关改动。公开美术交付须先过质量关和费用边界核验。继续沿用 Seed 状态事件入口；无法发布状态时持久化 pending，保留历史，恢复后补发。当前不因“用户要看效果”把未过关粗模叫作完成。
