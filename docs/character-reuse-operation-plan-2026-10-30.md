## 1. 先证明一指一键

仅在默认色三方GO后，从同一个冻结native派生动作副本。核心动作：左食指准备位 → 下降接触source白键014 → 该键小行程下压 → 食指与琴键回到准备位。其他琴键不动、右手保持准备位；不用整只手下沉。

- 复用原生FK指骨、原mesh和权重，不造手指，不缩指骨，不改头身。
- 先测原生关节小范围运动方向，再解一次皮肤触点。使用有限键面/外壳三角、邻键间距与实际完整渲染判断；骨尾不算指腹接触。
- 准备位目标约2.905mm悬停，最近邻相对余量只有约0.765mm。静态无交叉不能推断完整按压安全；数据是render-matched proxy，直接RENDER depsgraph尚有缺口。
- 失败停止条件：非目标键误触/穿键、手指塌陷或断腕、脸/身体异常、必须整手穿过邻键才能够到。出现这些先交motion judge，不扩展八键、头动或UI。
- 输出完整场景的start/contact/down/release/end帧、同场景手近景诊断、单次短片及测量receipt；生产帧必须含完整猫、双臂双手与全琴，不能合成独立胳膊。

独立motion judge必须真正看短片，而不只看几张still。验收“一次输入一次下压/回弹”，而非每次播放一段含很多次敲击的长视频。

## 2. 确认网页传输方式

并行做不含新动作的GLB静态往返实验：冻结native → render-matched evaluated snapshot → GLB → 重导入真实渲染。检查眼、嘴、手、纹理与体积。原生Geometry Nodes和Curve不能假定导出器自动保留；glTF也不支持原场景AREA灯，材质/几何保真与网页灯光应分别记录。

如果往返丢眼/丢嘴或明显降低精度，不在主站替换角色；保留Blender完整帧渲染路径。若往返可用，再检验前端连续插值、大小/加载时延和真实输入。任何web版须独立视觉judge，不把原生静态通过自动继承过去。

## 3. 再做八键和轻微响应

一个动作通过后才扩展source14–21中央八白键，按各键真实位置定位，左右手合理分区。每个键必须有不同触点，不能让ASDFGH都按同处。连续输入从当前运动状态转向新目标，音频立即响应；不排队播放多个敲击、不把整段动作重播、不以长交叉淡化造成双手重影。

头眼响应放在此后：小幅看向当前手区，乐句之间少量头部跟随/眨眼/呼吸。快速八音不能每音全头重置或机械点头。

## 4. 可操作交付

保留线上原版，新增独立轻量试验入口对比。默认页不下载大模型；用户明确进入3D试验才加载。实际浏览器检查点击/键盘 → 对应音符和唯一动作、快按/慢按/同时按/停止、重播、不同窗口尺寸；手机扬声器未测不能暗示已测。

commit/push脚本、许可和文档，大模型用附带SHA和署名的Release交接。公开发布仅来自public/的明确构建清单；确认Active部署、canonical文件与实际网页效果。进展/失败/恢复记录到既有Seed状态机制，保护站点鉴权，不把个人状态页反链进音乐玩具。

完整目标仍包含建模复用和实际操作；静态图、可导入文件或构建通过都不是已完成。吉他冻结的接触问题明确保留，只有新成熟模板/新证据才能重新开分支。

## 单键v1反馈：先修复可测的装配问题

v1原生试验已STOP，见 `research/miao-keyboard-single-key-v1-failure-2026-10-30.md`。近触食指可达且全手无交叉；白键下压0.363979mm时，新增23对键—底壳三角交叉，未制作clip。准确近触邻键余量为0.624895mm。该事实不允许以“PNG看不见内部”或“手没有穿透”签演奏通过。

两个后续假设须先独立诊断、再改静态副本：

1. 源键盘是静态造型，底壳顶面约z=.312m，原键底相邻，缺少此行程的键床净空。可以在保留CC0原壳/倒角/材质的派生副本上做最小必要的内部净空，检查闭合/法线/壳厚与外轮廓。不能默认换pivot或缩到看不见的行程就已解决；切槽属于待验证的少量适配，不是重造整琴。
2. 原腕位按viewport0最低皮肤点定位。恢复原生render2后，近触实际pad x=.06327529m，目标键中心x=.05731250m，向邻键偏约5.963mm。拟按真实render2皮肤重对中，仅调整原生IK腕的刚体位置并重新检查自然肘腕、其他指/邻键/壳/桌，而不改手的mesh/比例。6mm只是由当前差值推得的初值，尚未实施、不能声称修复或保证更大行程。

v2若获诊断支持，需先交新灰/色完整图与手近景重新三评；任何新P0仍阻止动作。现有静态包保持原字节和其有限评审结论。GLB运输退化、作者smile兼容性P0、吉他持琴FAIL分开保留，不被键盘进展覆盖。
