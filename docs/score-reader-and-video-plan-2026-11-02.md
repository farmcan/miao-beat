# 同屏读谱与视频回站尾卡 · 2026-11-02

用户问题：全屏读谱时谱子、琴键和猫不能同屏，缺少翻页；竖屏不能依赖强制旋转；演奏视频被分享后观众找不到产品。

按顺序完成：
1. 核对现状及参考。现有scoreBook位于workbench外，被全屏CSS隐藏；已有分句与score index可复用。Soundslice官方分页/适屏说明支持手动翻页与随屏布局这一产品机制：https://www.soundslice.com/help/en/player/advanced/241/scrollable-vs-paged-layout/ 。只参考交互，不引入其账号、播放器或作品。小红书官方作品榜2026-11-02文本提取为空；独立judge真实浏览器可打开完整榜，但页面日期为2026-10-24。榜单中的画声原帖当前无法进入，未亲玩不推断玩法；钢琴块/节奏大厨仅有榜单可见信息，不将平台数字解释为完成、分享或转化。既有Song Maker实际交互评审继续作为“谱/当前音/操作同屏”的参考。
2. 新增“看谱演奏”谱架：复用内置键位/音名/固定音级谱；每页4–6个事件、句子边界与页码；上一页/下一页、PageUp/PageDown、回当前；默认手动，主动选跟随后才自动翻。翻页不改曲谱选择或真人录音，不自动演奏。
3. 同屏布局：谱架内复用实际猫canvas、实际琴键与准备声音入口（DOM移位后可完整还原）。横屏左侧完整猫与选择、右侧谱页和琴键；竖屏紧凑猫展示、较少音符/页。停止、退出始终可达；软提示推荐横屏，不强制、不挡屏、不依赖旋转权限。所有布局必须用真实浏览器验证，不以CSS猜测通过。
4. 视频结尾约2秒尾卡：真实公开产品页预览、产品名、可扫描QR、短域名。QR指向固定公开产品URL，不包含身份/录音/访问凭据。复用qrcode@1.5.4 (MIT)构建时生成静态矩阵，运行时不引入QR SDK；保留来源和许可证。音频/JSON保留原语义，用户可关闭视频尾卡。尾卡不写入真人录音；取消、后台/失败/重试保护继续生效。
5. 回归与独立judge：分页完整性/边界/换曲/横竖切换/跟随与手动/演奏中翻页人输入保护；真实320/390竖屏、844×390横屏、原生视频与实际尾帧扫码识别；复评后构建发布miao-beat并核对生产字节/交互。开始、修复与结束留痕现有Seed状态机制。

验收核心动作：开谱→全屏→谱、完整猫、可点击琴键同屏→上一/下一页→实际发声→导出含尾卡→从实际视频帧解码QR并验证产品URL可达。手机实体触控/扬声器仍需真机，浏览器尺寸检查单独标注。

P0：不能覆盖琴键/退出/停止，不能裁断猫/爪/乐器，不能让翻页或跟随产生录音输入，不能丢失或自动覆盖已有片段，QR必须实际可解码而非外观相似图案。
