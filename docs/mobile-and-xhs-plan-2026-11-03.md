# 手机体验与小红书适配 · 2026-11-03

目标：优先修复手机核心动作，并验证能否直接发布到小红书小工具。沿用原完整橘猫，不扩展新玩法或角色建模。

按顺序执行：

1. 独立核验：三位judge分别检查手机UI、容器技术、产品上线。核实既有喵TI／喵塔罗平台经验，读取Creator当前官方开发口令与在线能力契约。
2. 最便宜平台探针：用已有CC0钢琴C4小样和完整idle／KeyA图，检查AudioContext、decodeAudioData、真人点击后的音频时钟／信号与整图切换。仅走官方模拟器／真机预览；普通浏览器只调试，不代替容器验收。若无法验证声画核心，不扩大正式平台适配或发布宣传。
3. 独立站手机修复：320短屏首屏应可见完整猫、声音入口和琴键；琴键touch-down保持低延迟，使用独立音域条／按钮换音域；导出完成后支持能力检测的系统文件分享，保留下载，取消／失败不丢文件、不误报笔记已发布。
4. 若探针通过，再复用既有数据／录音逻辑和平台桥接，打包Chrome61兼容、离线的钢琴最小闭环。正式包必须在容器实测；被禁的外链／互跳、下载、全屏调用与网站QR不进入平台包。若只分享图片必须说明图片不带声音。
5. 回归与发布：三角色复评；真实浏览器320／390竖屏、短横屏、录制／回放／导出验证；独立站源文件检查与Cloudflare生产验收。平台部署、审核、笔记挂载、Android／iOS普通用户体验分别记录。开始／异常／结束使用既有Seed状态事件。
