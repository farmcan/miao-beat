# 吉他单次动作修正 · 0.12.1 · 2026-10-26

用户指出“每次点击一个，都有很多个动作，像按了很多次”。真实线上复测K：记录只有1次，画面经过多个演奏姿态。代码复现一次K包含 idle→A→W→S→E→D→F→T→G→Y→H→U→J→K，共13条攻击过渡，松键回位又逆向播放。原验收证明了目标、补帧和记录能工作，没有证明“一次输入一次视觉弹奏”；前版自然度判断不成立。

## 修正

删除最短路径寻路。动画只由音频确认后的 `strike` 创建，RAF、松键或旧按键状态不再自行创建另一段演奏。

- 有审看通过的直接边：只播放这一条完整画面过渡到目标。
- 没有直接边：直接落在本次目标完整图，做一次小幅局部姿态往返。仅取该目标与相邻完整图之间靠近目标的1/4区间，不到另一个音符的端点，不串其他按键动作。
- 重复同一键：每次实际确认的输入触发一次短往返，按住不循环。
- 松键：在最后一次目标把位停住，不再从高音一路退回低音。失焦或切乐器明确重置。
- 新输入替换当前动作，不补播队列。声音、和弦原有15ms弦间隔、按键记录格式不变。

相距很远的换把仍有直接切换，这是本版明确保留的画面限制。试过idle→K直接RIFE补帧，中点按弦爪仍消失（Git审看文件：`design/guitar-motion-2026-10-26/rejected-idle-K.png`），因此没有把这个失败小样上线，也没有用多个别的音符姿态替代它。全部生产画面仍是猫、双爪、吉他完整同图，未新增分离肢体或几何拼装。

## 验收标准

本轮首要标准改为：一次点击只记录/发声一次，并仅出现对应目标的一次动作；按住不额外循环；松开不触发新的演奏；不同输入不会混成过时动作队列。检查画面经过的完整姿态与边，而不只检查最终到达哪个ID。

68项回归通过，新增/调整了K仅经过一条局部动作、无其他音符端点、松键保持最后把位的断言。正式源、部署与真实单击/连击验收发布后补记。没有把这些技术断言等同于用户认可动作自然度。
