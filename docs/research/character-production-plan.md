# 毛绒猫：可控 2.5D 动画资产制作计划

日期：2026-10-22。输入为 `design/character-concept-v1.png`（1312×1199，RGBA）；本轮已实际查看。这里只定义生产要求与验收，不生图、不改运行时、不新增依赖或付费服务。原概念图保留，不能覆盖成“动画成品”。

## 核心决定

**先做一个同机位的标准母版，再制作状态参考，最终交付头、两爪、乐器和补全底板的分层资产。** 推荐最小 8 张状态参考；第 9 张为可选的抬爪/回弹参照。它们不是 8–9 个互相随意替换的整幅场景。

原因：按爪共有 idle/left/right/both 四态，视线有中/左/右/上/下五态。如果直接切完整图片，独立组合需要最多 4×5=20 张，还没有计算抬爪中间态和吉他模式。分层后，头负责视线、左右爪各自负责演奏，琴和身体保持稳定，不需要整图组合爆炸。

先验收琴键模式的单爪与双爪，再做视线跟随。吉他先允许猫以通用轻扑/打拍互动；要画实际弹吉他时，另外制作同机位的吉他姿态层，不把键盘猫的两只按键爪硬贴到吉他上。

## 这张源图能用什么，不能直接用什么

可保留的角色身份：炭黑/深棕短绒毛、圆头短脸、琥珀大眼、橄榄绿耳机、圆壮小身体、卷曲尾巴、友好而好奇的表情。这些是后续每次编辑的固定参考。

当前遮挡和机位问题：

- 猫是 3/4 视角，琴斜向画面右下；左右爪尺寸与透视不同。直接镜像一只爪，会连毛流、高光和透视一起反过来。
- 两爪已经落在琴面上，爪后面的键面被遮挡；剪下爪后，底图仍保留原爪，或留下没有内容的缺口。用前端平移不能补出这些像素。
- 头、耳机、胸部、肩部重叠，整头旋转会暴露原来不存在的后颈/肩部；把一张带完整背景的“看左”图叠上去会覆盖爪和琴。
- 琴有深度，爪应在键面之上，但部分动作可被前缘遮挡。简单的上下两层无法总是正确处理接触关系。
- 概念图透明边缘在预览里有少量偏色轮廓，需要在浅色、深色和实际背景上检查；不能仅因文件有 alpha 就认为抠图已合格。

**不要把现图当纸片绕 Y 轴旋转来伪造正面，也不要整体图片跟鼠标摇晃来冒充猫在演奏。** 源图足够证明美术方向，尚不是能直接拆的 rig。

## 第一步：制作并锁定标准母版

先用原图作为身份参考，编辑出 `master-front-v1.png`。建议 1280×1280 的统一正方形画布（最终尺寸可调整，但整套只用一种）。母版用正面、略高于键面的固定相机，允许极轻的 3/4 立体感；脸正对观众，两爪都完整可见，键盘横向稳定，至少可以清楚区分左右接触区。

这一步改变相机，意味着琴的原始透视像素也会变化：**不能同时要求“真正改成正面”和“原图键盘每个像素不动”**。应该只在这一步统一重构，一经选定，后续全部状态严格保持母版的琴、机位、画布和比例，而不是每张重新换角度。

给主 Agent 的首次编辑要求：

> 以现有原创毛绒猫为唯一身份参考，保持炭黑绒毛、琥珀大眼、橄榄绿耳机、圆壮身体与尾巴，不换品种、年龄、毛色或耳机。改为适合可控动画的固定正面轻微俯视机位；完整小猫坐在同一台迷你键盘后面，左右前爪分别位于琴面左右两个明确接触区，略微悬于键面或轻搭，不互相遮挡。琴完全入画，键盘长边近乎水平，固定柔和棚光与投影。中性好奇视线看前方，不夸张歪头。透明背景，无文字、Logo、水印、场景、额外肢体。单一画面，不拼状态图，不画九宫格。为后续头、两爪和琴独立分层保留清楚轮廓。

如果正面母版失去原概念的吸引力，可保留轻 3/4，而不是强行追求绝对对称；但要接受左右爪独立制作、头部只做小角度视线变化，不能靠镜像或大旋转省素材。

## 第二步：8 个同机位状态参考

每张从**已验收的同一张母版**编辑；不连续把上一张变形图当下一张唯一参考，避免逐步漂移。主 Agent 每次传母版，并明确只允许哪些部位变化。状态参考可以先用完整猫+琴，便于叠加检查；提取运行时图层是下一步。

“左/右”始终按**屏幕视角**命名，不按猫的解剖左右。参考列表：

| 编号 | 文件建议名 | 允许变化 | 必须固定 | 用途 |
|---|---|---|---|---|
| 01 | `state-idle-v1.png` | 母版本身，中性睁眼 | 全部 | 所有注册与比较基准 |
| 02 | `state-left-contact-v1.png` | 仅屏幕左前臂/爪下压，爪垫/毛发在键面有轻微压缩，局部接触阴影变化 | 右爪、头眼、躯干、琴、镜头、光线 | 左单音/左打击；不是整个猫下移 |
| 03 | `state-right-contact-v1.png` | 同上，换屏幕右爪 | 左爪及其他全部 | 右单音/右打击 |
| 04 | `state-both-contact-v1.png` | 两爪同时触底，允许极轻肩部反作用 | 头部身份、琴的位置/透视、身体中心 | 双键和弦，验证独立层合成能否达到该参照 |
| 05 | `state-gaze-left-v1.png` | 眼球/眼睑、小幅头朝左关注；耳机与头一起保持刚性 | 脖子连接点、身体、两爪、琴 | 看向左侧输入 |
| 06 | `state-gaze-right-v1.png` | 同上，换右侧 | 同上 | 看向右侧输入 |
| 07 | `state-gaze-up-v1.png` | 小幅上看；不露出需要大面积补全的下颌/颈部 | 同上 | 指针位于角色上方 |
| 08 | `state-gaze-down-v1.png` | 下看琴键，仍睁眼，能看见琥珀眼 | 同上 | 指针位于键区/手机弹奏关注 |
| 可选 09 | `state-both-raised-v1.png` | 两前爪分别轻抬，露出琴面；不摆大挥手姿势 | 除双爪外全部 | 用于生成两只独立抬爪形态、检查被遮挡键面；不是默认 idle 循环 |

第一批只做 01–04：若这四张尚无法稳定注册，不继续生成视线帧。选定后再做 05–08。最多 9 个状态不是要求一次工具调用生成拼图；单状态单图更容易检查身份和接触点。

单爪编辑提示应重复：

> 使用已验收母版做精确局部编辑。只改变屏幕左前爪从轻搭到触底的姿态，保留同一爪的粗细、毛色、毛流、光线与腕部连接。动作是前臂/爪向琴面按下，爪端稍压扁，局部阴影随之改变；不要移动整个角色，不要把爪从手腕处切断，不要重画琴键。其余区域保持母版构图与视觉身份一致。画布、物体大小、琴的四个角和接触键位置完全锁定。

视线编辑提示应重复：

> 只让同一只猫小幅看向屏幕左侧，眼睛仍然是琥珀色玻璃感大眼，保留眼眶、鼻口、耳朵、耳机与毛发身份；头只做可与中性颈部接合的小角度变化，不转成新的侧面猫。脖子下端的连接位置固定，胸口、前爪、尾巴和琴完全不动，不添加新道具或新背景。

## 第三步：补齐遮挡内容，交付可独立组合的层

不能从完整状态图直接粗裁一个矩形就投入运行时。推荐交付以下层；每层保持母版画布坐标，导出 PNG/WebP alpha，原始 PNG 进 `design/` 保存，不覆盖母版。

| 图层 | 内容与约束 | 如何避免接缝 |
|---|---|---|
| `shadow` | 固定投影；可以很简单，但必须与琴/身体的位置一致 | 不随鼠标漂移；投影不烘在会移动的头或爪下方 |
| `body-clean` | 躯干、腿、尾巴，以及移除头/两前臂后补全的肩、胸与后颈 | 要求补出被遮挡区域，不能透明挖洞；头/爪根插入区域允许多保留一圈重叠毛发 |
| `keyboard-clean` | 完整琴体/键面，去掉覆盖键面的爪并补齐琴键与材质 | 同一母版的琴始终只有这一份，不随头或爪切换；去除原爪烘焙阴影，否则抬爪时出现“幽灵爪” |
| `head-center/left/right/up/down` | 头、耳机、胡须完整，向下含少量颈毛连接区 | 所有方向用相同颈部注册点，头层从肩/胸层前面覆盖；移动范围限于补全余量内 |
| `paw-screen-left` | 左前臂+爪，idle/raised 与 contact 两种关键形态即可起步 | 根部进入身体/头遮挡区；保留毛缘，不能在腕部画硬直切线；不要整块矩形遮住右爪 |
| `paw-screen-right` | 右侧同理，独立制作、独立锚点 | 不用镜像左爪；两侧可以同时 contact |
| `keyboard-front-lip` | 琴最前缘/局部需要遮住爪端的遮挡层 | 只保留必要前缘，不是把整台琴又盖一次；接触点不能被前缘吞掉 |
| 可选 `contact-shadows` | 左右小范围接触阴影，随触底显隐 | 阴影与受压形态同步，不能让黑色毛缘兼任悬浮阴影 |

逻辑绘制顺序：固定背景/投影 → 躯干与尾巴 → 琴的后部/键面 → 两前臂与爪 → 头（盖住肩/爪根结合处）→ 必要的琴前缘遮挡。实际头与琴的位置若有交叠，按母版深度关系细化，不为统一模板强改视觉。

**补全底板的编辑要求：** 从母版移除头和两前臂/爪，合理重建原本被遮挡的胸肩/颈部；另取完整键盘，移除爪和原爪的接触阴影，重建被遮住的键面。只补隐藏内容，不换乐器、不重排白黑键、不改琴体透视。此图是内部动画素材，不是给用户展示的“无头猫”。补全失败优先缩小可动范围，不拉伸原图去遮洞。

## 对齐、透明与锚点校准

1. **同画布导出，不自动 trim。** 否则浏览器相同 `left/top/width` 仍会因紧边框变化而跳。若最终为了包体裁图，必须同时记录每个裁片在母版上的 `x/y/w/h`，运行时统一用同一坐标系复位。
2. 校准至少 7 个点：琴四角、两爪接触点、头部颈根。再记头中心、左右腕/肩旋转点。用归一化坐标 `x/W,y/H` 存配置；**不要使用本计划凭空给出的像素位置**。主 Agent 在最终母版上标点后再定数值。
3. 头旋转轴在下颈，爪轴在前臂根/腕部；不是图层几何中心。琴角校准是检测“生成时琴悄悄移动”的基准，不能为迁就漂移把所有层重新缩放。
4. 用 50% 叠加检查静止区域。若参考状态里琴角/键缝明显重影，先做刚性平移注册；若是透视/键数量改变，应拒收重做，不能用复杂扭曲把琴硬对齐。
5. 毛缘保留真实 alpha，分别在白、暖纸、深灰上检查色边、黑边、白晕。半透明毛发不能一刀二值抠成硬轮廓，也不能用很宽的模糊掩盖裂口。工具“transparent=true”不替代此项验收。
6. 接缝区保留约 2–4% 角色高度的隐藏余量是起始建议，最终以最大动作下不露底为准；身体补全和重叠毛发比无限扩大图片裁片更可靠。
7. 展示到约 220–300 CSS px 时也检查，不能只看1280px原图精细度；关键爪动作应在小尺寸可辨，细毛不是动作反馈。

可用原生 SVG `<image>`/HTML 透明图层与 Web Animations API，或原生 Canvas 合成；不新增骨骼引擎即可实现。层级确定前不急于压缩/打 atlas，先保留可检查原片和元数据。

## 动画控制：输入优先，角色不排队

每只爪单独持有 idle/attack/contact/release 状态；视线与头部状态独立，琴和躯干不跟着整体晃。持续按住琴键时，音频仍按已确认的 one-shot 音源行为工作，不能因为画面爪在琴上就声称音符可持续发声。

- note-on 立即触发声音和局部动作，不能先等整张图片/视频加载完成。预备动作控制在很短的过渡内，触底反馈清楚，松开回弹。
- 快速同侧重敲时，从当前姿态重新进入短触底，不把每个完整300ms动画排入队列。对8Hz连续输入，角色不能慢半拍地补演之前的敲击。
- 左右同按分别驱动两爪；同一爪对应多个键时，用该侧仍按住的键集合决定是否保持触底，不能任意一个 keyup 就松整只爪。
- 鼠标与触控也需要按来源持有状态；两个手指按不同键时，抬起一个不能取消另一个。blur、pointercancel、切后台统一回中立。
- 视线对指针做限幅与阻尼，先采用中/左右/上下5个目标，不假装连续3D转头。方向切换加阈值/滞回，避免指针在界线上让脸反复跳；若用两张头部短交叉淡化，必须检查双眼/双耳鬼影，不自动视为平滑。
- 眼神关注可在触发音符时转向该区域，但不要让指针跟随与按爪争同一整图 transform。头跟拍只做微幅，不碰乐器位置；无输入时不必永远渲染60fps。

## 吉他模式：复用角色，单独制作姿态和乐器

本轮目标是真实尼龙弦单音和4个和弦扫弦，不做全指板模拟。可先让同一只猫通用打拍/轻扑回应，用清楚的吉他模式标签与声音表达切换；不能播放吉他音却把按钢琴键的完整概念图叫作“猫在真实弹吉他”。

后续资产应复用角色头、视线、耳机、躯干与尾巴；键盘与吉他独立作为 `instrument` 模式层。吉他需要一张同机位母版参考来定义琴身、琴颈、弦、左右爪与遮挡关系：一爪在琴颈/和弦位置，另一爪位于音孔附近扫弦。按单音只给拨弦小动作，扫弦给一次可辨的跨弦动作，不伪造每个具体把位的手指运动。

“左爪/右爪”仍按屏幕位置命名；哪个负责按弦、哪个负责拨弦由该吉他母版决定并写入模式配置，不拿键盘左右音区语义直接套。可复用头与身体，但应制作吉他专用 `fret-paw` / `strum-paw` 形态；大幅改变前臂姿态后重新检查肩部连接和琴身前缘的遮挡。

为了支持两种乐器，不需要现在加入真3D。真正决定是否升级3D的是未来是否需要自由改变观察角度/灯光，而不是多了一把吉他。

## 最小验收与停止条件

| 检查 | 通过条件 | 不通过时做什么 |
|---|---|---|
| 母版身份 | 和概念图是同一只猫；小尺寸仍有圆脸、琥珀眼、绿耳机和毛绒质感 | 先修母版，不生成一整套“不同猫” |
| 4个手态参考 | 琴四角/键数/机位稳定，单爪动作清楚，另一爪不跟着漂 | 退回同母版局部编辑，不靠全图旋转/缩放补救 |
| 分层还原 | 全部 idle 层叠回后等同母版观感；无原爪残影、毛边裂缝与肩部破洞 | 补全清理底板，检查层序和根部重叠 |
| 独立组合 | 左下压＋看右、右下压＋看上、双下压＋看左都自然；琴不动 | 优先修层/锚点，不继续补20张整图 |
| 连续输入 | 8Hz短敲与左右并发不排队、不漏视觉回应，keyup/取消能复位 | 缩短动作并改可中断状态，不换更重的引擎掩盖调度问题 |
| 透明轮廓 | 三种底色、100%与实际显示尺寸都无明显色边或矩形遮挡 | 精修alpha和隐藏余量，不用整体发光遮盖 |
| 吉他预留 | 头/身/乐器分离，能换mode图层；未制作弹吉他pose时准确称通用反馈 | 不强行复用键盘爪，不新增真3D依赖 |
| 发布负担 | 预载关键层后首次按键无下载等待，失败有现有SVG回退；压缩体量与手机解码实测 | 先减状态/尺寸，不让第一击等待大视频或整套角色库 |

建议主 Agent 的下一次生图顺序：**正面母版 → 左/右触底 → 双触底校验 → 清理底板/分层 → 五向头部 →（可选）抬爪参考**。每一步都有可拒收的具体条件，没通过就不扩大下一批。原始生成图、编辑提示、源母版哈希、导出裁片与锚点都记录下来，之后换音源或换吉他姿态不会失去来源和对齐依据。
