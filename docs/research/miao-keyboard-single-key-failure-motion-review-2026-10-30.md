- 同状态全手对组件三角交叉0，目标skin仍有 **+.092626mm**微间隙，最近邻 **+.312001mm**。不能说此次是手指已经穿邻键；down只是首猜，也尚未完成原50±15μm触点求解。
- contact_solve_1目标gap为 **+.063241mm**，准确邻键gap为 **+.624895mm**。此前聊天约.6816mm的简写已纠正，不继续引用。

forensic不只是BVH计数：有真实边—三角交点和两个inside键顶点。6.438μm是所测顶点的最大nearest深度，不是连续面的最大穿深，不能用它忽略23对。当前PNG看不出壳内交叉，同样不能关闭P0。

## 两项推断与证据缺口

**键床：最小空腔有依据。** 原prop白键底源z≈.042m、壳顶源z≈.042m，摆放后都约z=.312m，原本近乎齐平。源GLB无native hinge / action；当前后端bbox厚度中点铰轴是项目假设。不能把静态成熟prop当已具备机械净空，也不能从这次失败判源模型差或cat无解。

先核固定铰轴与拟支持行程，再定空腔；不要只为当前失败frame挖孔，之后每加一点行程继续挖。改pivot可能消除局部后端切入，但因键底 / 壳顶齐平，不能预先承诺仅换pivot就解决整个键床。

**腕对中：方向正确，−5.96mm仅是near-contact起点。** 本角色据JSON重算：

| render2 ready | .063048355m | −5.735852mm |
| contact_solve_1 | .063275293m | −5.962789mm |

恢复render2后，旧viewport0对中不再等于实际低指腹对中。最低点也从vertex15650切换到15647，不能依赖单个min顶点在全程不变。root约−5.96mm的判断对near-contact算术成立，未证明腕控制器平移会使实际skin全程严格刚体同移。

应保持cat geometry与腕world朝向，通过原生腕控制器在正确空间作一次确定性world-X修正，不直接挪独立手mesh、不把world-X误当local-X。移动后重新测实际低指腹区域、可用键面、全手 / 袖、reach与腕关节。当前触面normal z≈.9808，位于倾斜倒角，不宜只对bbox中心便称接触斑最优。

“margin”要分口径：当前近触邻键垂直gap是.624895mm；若约.68mm指横向可用面余量，须另给真实边界。raw键bbox边距在该点约1.733mm，也不是倒角内可用顶面余量。

## 最便宜的下一步

1. **先只读查键，不动cat：** 固定一次单键运动定义、最大前端行程与回位；用实际键底 / 壳截面和扫掠确定是否缺净空及必要well范围。不换frame、不扫pivot。
2. **一轮有限派生修正：** A，按render2实际接触斑作确定性腕对中；B，只有必要时修改CC0底壳的局部隐蔽键床。分别保存before / after与边界。保留可见外壳 / 键面 / 材质、成熟cat base mesh、右手 / 头身与原骨长；不删除整底板或另造键盘。检查空腔壁厚、连通、法线与修改声明。
3. **先回静态门：** 新位置 / 底壳给新pose与geometry hash，完整front / 3Q、双手和承托重新gray三评，再同pose默认色三评。旧静态GO不继承，三评完成前不做动作。
4. 新静态通过后才重做同指同键关键状态。任何新增手 / 键 / 壳 / 桌碰撞、未声明姿态补偿、需stretch / 改源手形 / 降render精度，均STOP；不扩八键。

更优雅的是让**实际接触口径与固定机械工作区先成立**，而非继续求几个Euler角迎合一个边缘触点。不是把邻键gap当唯一目标：对中后还需检查其它手指、黑键、腕袖与完整图自然性。
