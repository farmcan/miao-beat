# 首版结论：让猫把身边的声音弹成歌

2026-10-22。性质：已交付首版的复盘，以及下一步主题与传播实验建议。热点证据、许可和实现审计分别见后续章节；下文的转化目标是实验门槛，不是已有用户数据。

## 先给判断

**保留 Miao Beat 的猫咪音乐工作台，下一步用“什么都能弹”的声音玩具系列扩展。** 猫是稳定角色，瓶子、玩具、生活声音是每期的新乐器。用户能一眼知道自己在做什么：按一下有声、跟节拍弹两句、把自己的版本交给朋友。

首版已经是可玩的轻量乐器：真实钢琴、马林巴、尼龙弦吉他和八件架子鼓；调速节拍器；短参考谱；本地演奏事件导出/导入/回放；原创分层毛绒猫；手机大键与演奏模式。它解决的是“让我弹出来”，不应增加滚动音符、连击惩罚或复杂工程编辑器。生产版本与验证边界见首版审计。

我建议下一项先验证**猫咪瓶子乐队**，再尝试有来源、素材可用且仍在传播的短期热点。瓶子目前是提案，没有悄悄加入线上音库。竹知了和人物滑杆也没有直接复制上线。

## 为什么这条路线更适合

| 路线 | 用户第一眼得到什么 | 留下和分享的理由 | 主要代价 | 判断 |
|---|---|---|---|---|
| 每次追热点、换整站 | “我认识这个梗” | 转发同一个笑点 | 热度衰退后缺少继续玩的理由，界面与素材反复重做 | 作为临时入口，不作主产品 |
| 完整虚拟乐器/DAW | 丰富功能 | 有经验用户认真创作 | 手机门槛、音频与编辑复杂度明显上升 | 超出这次范围 |
| 猫咪声音玩具系列 | 可爱角色把熟悉声音弹成旋律 | “听听我弹的”与“你来接下一句” | 每期仍需好音色与清楚手势 | 推荐；用同一个演奏内核验证 |

这些是设计推断，不是用户调研结论。当前没有经过核实的来源、留存或分享转化数据；不能凭 GitHub stars 认定某种玩法更能留住本项目用户。

[Patatap](https://www.patatap.com/)的直接参考是按键、声音和画面的即时联系；[Typatone](https://typatone.com/)展示的是文字也能变成可表达的旋律。我们的差异应落在**可识别的小旋律 + 有角色的真实声音 + 极轻的作品交换**，不能只停在换一只猫或重复随机音效。前述产品是机制参考，未在本轮取得可对比的活跃用户与留存数据。

## 三类题材分别怎么用

### 1. 瓶子：先做长期能玩的原创乐器

一排八个瓶子，对应 C 大调一组 do re mi fa sol la si do。桌面继续 A S D F G H J K；手机用大面积瓶身触点，横屏完整展开、竖屏可横移，颜色只作辅助，保留数字/音名。猫的左右爪敲相应侧的瓶子，瓶口或水面短暂震动，动作不要遮住按键。

第一轮优先**敲瓶**：短而清楚的起音更容易与现有 one-shot 事件吻合。若验证吹瓶，则先按一下触发固定时长的气声，不默认要求麦克风或把“按住时长”硬塞进旧文件。持续吹奏以后需要明确 note-on/note-off 与新版格式。

科学上的方向不能画反：吹瓶时水越多、空气越少，音通常越高；敲同类玻璃瓶时加水通常使音下降。等间距水位不等于等间距音阶。首个乐器可以直接用校准后的八个声音，并标“调音示意”；不要宣称任意瓶型和水量都能精确得到对应音高。出处、近似公式和开源候选检查见“瓶子乐器与主题”章。

最低成本的证伪动作：先让少量试听者比较钢琴与敲瓶的同一段两小节旋律，若瓶声听不清旋律、刺耳或换音后失真，先修声音，不追加角色资产或关卡。

### 2. 竹知了：借“熟悉声音变旋律”的机制

已找到用户所指的高匹配网页玩具及代码，详见热点证据章。它让熟悉的物体随动作连续出声；这提供的是从生活声音到可玩交互的启发。现有源码许可不能直接推导为可公开 fork，采样来源也须独立核对。

如果做我们的版本，先确认声音权利，再测一个有稳定基音的短采样。`rate = 2^((targetMidi - rootMidi)/12)` 可把根音转到目标音；变速也会改变时长与音色，噪声/摩擦声不一定能清楚变成 do re mi。因此至少逐个试听八个目标音，必要时用新录制或自制声音，不把任意一段“哇”简单乘速就当成完成的乐器。

保留可识别的起音，再让用户弹出熟悉旋律，比整站仅重复同一个声音更值得验证。这是我们的设计假设，不是对原产品增长的归因。

### 3. “梁文锋滑动变祖器”：核实后作为交互参考

本轮找到了相关网页项目；目前核到的核心是滑杆位置对应不同形象/称呼，并非已经完成的音阶乐器。不能把一个人物梗的存在写成“这个音乐玩法已验证成功”。代码、人物图片与声音的许可也不能混为一谈。

可借的是**一个连续动作带来明显变化**：例如猫的表情、瓶中水位或合成器音色随滑杆改变。若用于弹歌，应提供“吸附到音阶”与当前音名；若只是音色变化，则固定音高、只改变亮度/粗糙度，避免用户不知道自己在控制什么。人物素材不是该机制的必要组成。

## 同一个内核，少量可替换的主题

每个主题只定义声音、音域、触发方式、短动画、来源与许可；节拍器、按键、事件时间和回放继续复用。首版已有真实采样引擎与旧文件兼容，不要因为新皮肤悄悄让旧片段换声音。

下一主题的事件必须能标识主题与声音版本。现有 v2/sample-v1 不能随便新增无元数据的瓶声；需要新引擎/主题版本或明确扩展的预设枚举，保留旧文件映射。未实现前不要用钢琴声音导出文件却标成瓶子。

默认只展示少量能理解的选择：真实乐器在前，声音玩具作为另一个组。临时热点用一张有日期的主题卡进入；热度过去也能归档，不更改默认品牌或让老作品失效。

## 分享的核心：交换一小段自己的声音

首版可行路径已经是：选乐器 → 开节拍器 → 弹两句 → 记录 → 导出小文件 → 朋友导入回放。没有账号和音频上传。文件很小不代表没有传播摩擦：在聊天里发附件、让朋友再导入，仍有操作门槛。

下一次只挑一个降低摩擦的实验：给短片段增加“生成回放链接”，接收方先点播放，再选“我也弹一个”。进入页面不自动播放；长片段仍保留文件；不自动上传、不开公共作品墙。链接编码需要独立长度上限、版本校验和失败提示，这次未实现。

可以围绕两种内容发起：

- **同曲换声音**：同一个生日旋律，钢琴/吉他/瓶子分别是什么感觉。让朋友选最喜欢的声音，并能直接试。
- **接下一句**：前两小节作为开头，接收方导入回放后自己重新演奏一段；先验证用户愿不愿意接，再决定是否做无损接段与多轨。

不以强制分享解锁、排名或“不会弹就是失败”驱动参与。作品的理由是“这是我弹的”，而不只是替产品转发。

## 推广与数据：先看能否完成，再看热度

现阶段人群是待验证假设：会被猫/声音吸引的轻度玩家、想弹熟悉旋律的新手、愿意录一小段给朋友的人。没有本项目真实来源证据，不能将先前 MiaoTI 的抖音流量等同于 Miao Beat 用户。

手动推广先准备一段真实屏幕演奏：前3秒直接展示猫敲出可辨识旋律，随后给键位和可玩链接。分别测试“生日祝福”和“同曲换声音”，每个入口用独立 campaign 参数；不拿未经授权的用户作品当素材。

如后续接入匿名聚合事件，应在接入与生产验证后才报告数字：`instrument_ready → first_note → recording_started → recording_completed → export/share → imported_replay_started`。不采集原始按键、旋律内容、身份或麦克风。

一轮小测试可以先找10位愿意尝试的人：目标8位能在30秒内发出第一声，6位完成一段，3位愿意主动给朋友听。它们只是人工测试的决策门槛，样本太小不能推断市场转化率。若首声都困难，先改入口和加载；若弹完却不愿分享，先改内容和声音，再考虑社交功能。

## 分阶段与停止条件

1. **本轮已交付**：可玩首版、当前生产字节核验、详细研究、主题取舍与公开阅读页。实机触屏、多点触控、原生全屏、端到端延迟及人类听审仍单列待验。
2. **建议下一步**：先听审四组真实音色，修最不舒服的一组；再验证一排八瓶的两小节小样。先声音后精细美术，不同时开三个热点。
3. **仅在闭环有效后**：短片段链接回放；用户确实交换作品后，再决定是否值得做接段或loop。
4. **热点准入**：有可核传播来源、有可用素材或原创替代、有可辨音高、有一条能玩出来的小旋律、有退出和归档方案；任何一项缺失则停在研究。

下一次需要确认的具体产品选择是“是否把猫咪瓶子乐队作为第一个声音玩具主题”。当前研究建议不等于已经授权复制人物素材、抓取别人的声音或新增社交后台。

研究也提出了短视频/音画导出作为社交成品的替代方向；本轮优先建议链接回放，是因为它与已有的小事件文件更接近。先观察“接收方能否打开听到并继续弹”，再决定视频导出的开发成本是否值得。两者均未实现。
