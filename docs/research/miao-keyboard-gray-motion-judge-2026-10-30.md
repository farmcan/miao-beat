## 实际手腕、关节与手指读感

完整front / 3Q中双肘保持弯曲，手从袖口自然向前到键面，没有明显的最大伸臂、腕部反折或掌根被琴颈挤住的读法。手掌朝下、两侧食指相对更低，其它源手指保留放松弧度，形成“准备按键”的清楚静态意图；不是已经按住一片键盘的重压姿势。

双手近景能分辨源四指和指间空间，袖口、腕、掌背、趾端的连接清楚。hands-top中两手分处中央区两侧，指端没有互相交叉；较低的食指末端可从其余手指中识别。源手的faceted mesh层次在大crop可见，工艺角色仍需判断，但本角色没有看到必须重建成熟源手才能解释静态关节的P0。没有因四指而要求加第五指，也不把卡通手势认证为真实钢琴技术。

相较原参考，当前是大头飞行员猫、长密键列与单指悬停；参考为橘色梨形猫、八大白键、双短圆爪靠键面。差异很明显，是否达到可爱 / 品牌表达由身份与craft角色独立判断。本角色允许的是当前成熟模板可形成合理键盘悬停动作基础，不把它说成已经还原原图身份。

### 最近邻余量是未来按键的关键限制

最近邻键3.208mm垂直gap只比目标键2mm多约 **1.208mm**。若以后仅把整只手 / 指腹刚性向下移动，目标触键后再下降超过约1.2mm且投影关系维持，就可能先用其它部位碰到邻键。实际最近邻3D距离约2.699mm与垂直gap含义不同，不能拿一个替代另一个。

这里没有键程、旋转轴或实际按下姿态，**不据此判所有独立按键必然失败**。结论是不能直接复制2mm下降为完整演奏动作，更不能整手下沉去假装单键。后续若静态全三评通过，应使用源支持finger控制与真实目标键行程，逐状态检查指腹、邻键、黑键、壳体、回位及手的自然性。

## 中央八白键：工作区有依据，八键验收仍unknown

键盘原宽720mm、40白 / 28黑，中央source14–21八白外缘约130.0175mm。当前食指目标分居两端，说明该区并非远在双臂之外；它是便宜且值得继续核验的工作区。但没有另外6键的真实腕 / 指pose，也没有跨区移动路径或交替手策略，因此**不能签“八键全部可达 / 可独立按压”**。

未来按键gate至少应包含八个真实目标各自的静态下压与回位、两端 / 中央键、黑键邻近处，以及快连按接管。实际skin不得靠拉伸或穿邻键到目标；不得只按key-object变换而没有匹配手势，再称手已弹奏。以上是未来验收条件，本轮没有制作任何这些状态。

## 手机UX：目前是重要缺口，尚不构成当前静态手姿失败

完整front中脸占主要注意力，68键看成细长黑白条；hands-top能读出指端，但它是大crop，不能代替产品整帧可见性。中央八白仅占整琴宽约 **18.06%**。即使键盘在手机上占满360px，中央八白合计也约65px、单白约8px；若完整猫构图令键盘只占约190px，中央八白约34px、单白约4px。后者仅为布局估算，**没有浏览器 / 真机实测**。

这种尺度下，小键行程或相邻指位差异可能几乎看不见。最终不能只靠角色指尖的几像素差让用户判断是哪一音、是否触发。建议保留清楚的独立八键输入UI、按下高亮 / 音符反馈与映射提示，让角色提供伴随反馈；需在真实产品尺寸验证，不能仅靠放大掌部crop签UX通过。全身 / 双手 / 整琴同帧要求仍保持，不建议为掩盖这个缺口只交独立手部镜头。

这项目前是**产品可见性待验**，不是当前腕关节结构P0；若实际目标布局中无法看清八键反馈，则产品gate应失败并调整展示 / 反馈，不用静态接触成功平均掉它。

## 键盘无支架：明确待补的场景缺口

front / 3Q中的键盘没有支架或桌面，当前悬置；原参考则有明确承托。手在2mm悬停，不能被解释成正在举着或托住整琴。当前图作为静态接触诊断可以继续默认色比较，但**不是完整可信的最终演奏场景**。

本角色把它列为进入最终整场景 / 产品交付前必补的有限场景项，不以它重新否定当前手腕可达性；也不把后续颜色渲染称已补承托。应优先复用合适的成熟支架 / 桌面，在不改当前手琴姿态的前提下再验证脚 / 身 / 乐器接触和完整同帧。若承托加入必须重新大改角色或琴位，须回到新静态gate，不能沿用本pose的GO。
