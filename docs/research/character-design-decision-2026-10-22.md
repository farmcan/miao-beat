# 猫乐手：三种形象与交叉评审

日期：2026-10-22。用户判断当前猫“不够可爱”“没有音乐范儿”，要求多位 subagents 分别设计、再评价选优。本轮目标是确定可视的角色方向与动画制作顺序。概念图与上线角色严格区分。

## 本轮选择：C · 淘气小乐手

三位评审各自完整查看三张实际生成图后，**第一推荐均为 C**；主 agent 也选 C 进入下一步。选中的是“认真投入，弹开心了会小得意”的性格和表演方向。钢琴格在盯手、身体前倾，吉他格的扶颈与扫弦有分工，鼓格的抬手、脚踏与短促得意能读出兴致。耳机可以保留为识别元素，但不是胜出原因。

| 独立评审 | 排序 | 关键取舍 |
| --- | --- | --- |
| 造型 / A 设计者 | C > A > B | C 的开放眼神、口鼻明度和身体投入更亲近；A 折耳换边，A/B 低眉容易偏冷 |
| 动作 / B 设计者 | C > A > B | C 的三件乐器各有动作意图；需要把高光姿势收回为短促、可控制的反应 |
| 互动与实施 / C 设计者 | C > B > A | C 最像自己玩进音乐；B 固定坐姿和身份更稳，制作风险相对较低 |

第二、第三名有分歧，保留这些分歧，不用总分掩盖取舍。A 的软团比例和 B 的统一机位可作为制作参考，不把不同猫的脸、耳、身体拼接成第四只。三案都在灰色毛绒、暖底的相近审美内探索，尚未覆盖扁平插画、黏土等所有风格；C 是**本组最适合当前目标的方向**，不是经用户实验验证的普遍最优解。

### C 进入制作前必须修的三件事

1. **有一张放松、自然睁眼的基准脸。** 开口、眨眼和小得意仅作短回应，鼓模式不能永久闭一只眼；统一三模式的脸型、机位与头身比例。
2. **动作有准确触点。** 去掉吉他扫弦爪的固定运动模糊，鼓棒真正落到鼓面；落键/扫弦/打鼓分别设计，不靠整猫循环摇摆。
3. **按小舞台生产与验收。** 简化支架与脚踏细节，补齐被道具挡住的肩根和前肢，做可拆组件。先做一个乐器的6–8秒小样，再扩展三乐器；现概念板不可直接充当 rig。

下一步的小样包含“松弛等你 → 预备时低头 → 按键时接住 → 句末回看小得意”。让性格从动作里出现，不持续向用户挤眉弄眼。

## 为什么现猫不够打动人

三位独立评审分别查看实际产品截图、原始概念图与四组件素材，并从造型、动作、互动情绪提出问题：

- **像等着拍照**：正脸直视、左右架肘双爪和高度对称的姿态，让它像摆在舞台上的商品玩偶。
- **看不出正在听音乐**：三件乐器共用相近手势，视线、重心、发力和收尾没有表达演奏意图。耳机只提供身份提示。
- **用户越认真弹，越容易看不到猫**：角色与主要输入区距离较远；手机横屏提示展开时舞台收起。微表情再精细，也可能不在注意区里。

不继续通过眼睛变大、毛发变密或循环整身蹦跳解决这些问题。需要一只性格清楚、对乐器有注意力、会回应用户的小猫。

## 三个独立设计任务

| 方案 | 性格方向 | 要验证什么 |
| --- | --- | --- |
| A · 软萌卧室乐手 | 温柔、短圆、认真陪你弹 | 安静时是否也可爱；演奏是否有注意力，避免退回商品玩偶 |
| B · 松弛即兴猫 | 听得进去、身体有 groove | 音乐感能否来自姿势和重心，避免成人化的酷与堆配饰 |
| C · 淘气小鼓手 | 有童真、会偷着得意 | 是否有记忆点和输入反馈的潜力，又能迁移到钢琴与吉他 |

每位设计者使用内置 imagegen 生成一张原创概念板，同一只猫分别演奏钢琴、吉他、架子鼓。没有使用其他作品角色。生成图是静态提案，不是完成的透明组件、关节或动画。

## 评审方法

概念板出图后，三位评审分别实际打开全部三张图，先独立给出排序和具体可见依据，再由主 agent 合并取舍。每个人都设计过其中一案，因此这叫交叉评审，**不冒充双盲实验或真实用户偏好数据**。主 agent 不提前告知期望赢家。

比较五件事：猫本身是否可爱；是否像在听与演奏；缩到产品尺寸时是否可读；三种乐器的身份是否一致；是否能以少量分层素材实现即时互动。装饰复杂、画面精致、静态图有动势，不等于运行时已经好玩。

## 动画落地顺序

1. **先固定猫的身份与相机**：选定脸型、毛色、短爪和角色性格，生成一致的中性/专注/短闭眼满足状态；固定正面略俯的镜头与接触平面。不要直接把三张透视不同的成图贴入同一个 rig。
2. **乐器驱动手势**：钢琴是小幅下压、清楚回弹；吉他一爪扶琴颈、一爪扫音孔；鼓是左右棒落点与对应鼓件/镲的短反应。身体跟随短句的重心，不每个音都大幅摇头。
3. **建立四阶段**：待机松弛；预备拍注意力向乐器；输入时接住发声；短句结束轻轻回看或得意一下。保持自由演奏，不为没跟上谱的用户做失望脸。
4. **先可信、再卖萌**：清掉慢帧后过期爪动作、失焦时停止未结束动作；CSS held 与短击动画使用明确的控制权。现有 `12%/35%` 关键帧经过整体 easing，不能直接推成 22.8/66.5ms 的实际接触时刻，也不能据此宣称量出了音画延迟。
5. **与输入共同可见**：桌面、手机分别检查猫、时间条和琴键的关系；在有效触控面积基础上保留可读的角色反应位。减少动态偏好时保留明确的静态状态反馈。

## 验收与停止条件

先做同音色、同八音片段的短对照：待机、预备、左右交替、同侧快速重击、收尾、失焦停止。观察触点、回弹、注意力和结束状态；不拿不同音乐、背景或渲染分辨率替代角色比较。

如果小尺寸下读不出琴/弦/鼓的接触，先修姿态与构图；如果分层后角色身份明显漂移，先修素材；不在这两项未过之前扩展大量表情、视频或3D技术栈。静态概念评审不能证明插值自然度、触屏延迟、音质或用户留存。
