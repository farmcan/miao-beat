## 几何与工艺观察

| 项目 | 实际看到的结果 | 判断及限制 |
|---|---|---|
| 丰满度 / 前后体积 | 三分之四灰模显示头部有明显前后深度、下颌与面颊包裹体积，躯干是圆腹；没有只从正面成立的扁壳感 | 基础体积通过筛选。原 Miao 是更大的下腹梨形；本候选是大头、小圆躯干、工装短腿，改色不会把比例变成原图 |
| 掌部与手指 | 手部近图可分辨一根侧拇指与三根前向手指；掌指有连贯的蹼部过渡，指根厚、指尖圆，非四根独立细管拼接 | 基础手工艺通过筛选。偏卡通手套式结构，当前是伸展手背视角；掌心、握拳压缩、拇指对掌和指腹贴弦尚未实测 |
| 手腕 / 袖口 | 手掌从有厚度的袖口自然伸出，腕部宽度有过渡 | 可直接复用原手；袖口是否挡住琴颈、腕弯折是否挤压需静态姿势证实 |
| 耳与头 | 耳朵有厚边、内耳杯状凹面，头脸有口鼻 / 下颌的连续曲面；面颊侧部是明确的风格化毛簇，不是随意插入的尖锥 | 工艺成熟。护目镜、巨大正圆眼、侧脸尖毛簇构成另一角色身份；若保留 stock 方向可接受，但不能称为原 Miao 精准复刻 |
| 服装 / 配件 | 翻领、口袋条、拉链、袖口、裤脚、护目镜均有实际几何层次，圆角尺度相对一致 | 精细度明显高于粗糙 primitive 试作。衣服轮廓不会因改橙色而消失；“直接脱装成裸猫”没有证据支持 |
| 灰模表面 | 掌部、面颊和腹部大曲面大体平顺；局部指端仍可见轮廓分段，灰模里的眼圈、眉毛与嘴边有较强的浮雕感 | 这些是待最终镜头复核项，不据 Workbench 图直接判定源材质失败。眼圈 / 眉毛的成片观感与上游 camera / shading 依赖有关 |

审计支持上述掌指观察：`GEO-hands` 为 1,138 基础顶点 / 1,134 面，有 armature、corrective smooth、subdivision 和法线 / 轮廓节点修饰器；`RIG-Cat` 有双侧 Thumb、Index、Middle、Pinky 的两节 deform 链及相应 claw，三根前指另有 carpal。骨名存在不等于变形已验收。

四指是拇指加三根前指，不能宣称对真人吉他四根按弦手指逐指教学。对于音乐玩具的一般握琴 / 拨弦表达有试用价值；具体和弦姿势是否成立留给实际静态接触验证。

## 材质来源质量与改色可行性

作者预览的成片有协调的粉色耳鼻、深浅毛色分区、蓝色工装、红色配件以及清晰的材质层级，脸与手的体积能被读出。它体现的是成熟的绘画式 toon 工艺，不是原 Miao 的短绒玩具材质。原图中的微绒、柔和大面积照明、木吉他与奶油色腹部不可自动算到此模型头上。

本地审计确实记录了不同材质槽：头为 `cat.fur_dark` / `cat.fur_bright` / `cat.inner_mouth` / `cat.fur_lips`，耳另有 `cat.ear`，手为 `cat.fur_dark`，身体为 `cat.suit_blue` / `cat.suit_red`。存在 4096×4096 的 packed `cat.base_color`，无外部 linked library。这为**保持几何和服装结构、仅调整毛色与服装配色**提供了合理基础，不需要新造掌指或耳头。

但审计没有导出材质节点完整结构，也没有本地最终着色图，所以尚不明确改色应落在共享节点、贴图分区还是其他驱动参数。不得把简单改一个 Base Color 说成已验证方案。`GEO-body` 的材质和实际预览都表明其外形就是工装身体；隐藏领口和拉链不保证底下存在完整裸猫皮肤。

最低风险的静态试验方向是：保留 stock 的成熟几何和工装，调整毛色 / 衣服色以形成协调的橙猫版本；琴作为完整实物道具与角色同一镜头呈现。若要求必须变回原图的裸身大梨形，则“只改色不改 geometry”不足以满足，该要求应触发换模板，而不是隐性扩大成重建猫。

## 兼容性与生产阻挡项

文件 6,292,093 bytes、packed 贴图和无外链是可获得性的优点，不是运行性能或成品质量指标。预览 receipt 指定 56 个实际可见对象，基础顶点共约 1.8 万；audit 中只按 `hide_render == false` 统计会得到更多对象，不能混用这两个口径。当前尚无 evaluated 网格、最终渲染耗时或浏览器资产体积预算证据。

| 优先级 | 阻挡 / 风险 | 必要证据与动作 |
|---|---|---|
| P0（最终着色 / 动画前） | Scout 记录作者要求 Blender 3.6；5.2.3 仅在禁用 autoexec 的条件下读取。856 条对象 driver 中存在相机依赖，当前有被阻止的 expression；不能认定完整材质和控制链兼容 | 优先在作者支持环境检查。审查需要的嵌入脚本 / driver 后决定兼容路径；不以全局开启不可信脚本作为“修好”证据。不要求本轮执行代码 |
| P0（美术交付 / 动画前） | 没有改色后、实际抱琴的本地着色 still；原作者持笔 / 夹板只证明上游一般持物能力 | 一个全身灰模抱琴 still，匹配镜头的脸与两爪裁切，随后一个相同姿态的本地着色 still；完整猫、双臂双爪与琴在同一画面内 |
| P0（动画扩展前） | 未见弯指 / 掌心对琴颈、拨弦爪与琴面、袖口 / 躯干 / 琴之间的实际接触 | 用原生 rig 验证静态接触，指腹贴弦、拇指绕颈、腕与袖口无明显塌陷 / 穿插、前臂可放松承托琴。若姿势无法成立，换成熟模板 |
| P1 | 与原图的身份、比例和材质方向不同；近景浮雕眼圈 / 嘴边是否在最终 shader 下自然未定 | identity reviewer 依据用户允许优秀 stock 的新边界评价；craft reviewer 在本地最终着色 still 中复评圆润度、眼口融合、材质层级 |

这里没有发现足以否决“进入静态试验”的 P0 几何缺陷；上表 P0 是最终交付 / 动画扩展阻挡。不要把两种门槛混成一个 pass。

## 两道 gate 的明确签署

1. **Asset → 静态改造试验：GO（craft 角色）。** 已见成熟的完整头体、耳部厚度、四指掌部与服装工艺；不需要也不应回到自造粗糙猫或手。允许的下一步仅是兼容性验证与一次静态改色 / 抱琴结果，不能据此扩动作。
2. **改造后灰模 / 着色静态 → 最终产品 / 动画：HOLD。** 当前证据没有完成匹配镜头、真实握琴接触、本地最终材质及兼容性验证。仍须三角色分别复审；某一 P0 未解不能用其他角色打高分抵消。

本次没有动作 clip、页面交互或音画响应证据，均为未验证 / 不适用。评审文档为本地内部证据，公共状态事件由主任务统一写入既有 Seed 状态机制，避免重复或提前宣布美术已交付。
