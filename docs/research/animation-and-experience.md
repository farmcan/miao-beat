# Miao Beat：动画与演奏体验路线研究

研究日期：2026-10-22（Asia/Shanghai）。本轮目标是节拍器、自由演奏和轻量创作，谱子提供参考与试听；不做落键音游、分数、连击、通关或强制跟弹。路线研究与本轮 UI 原型并行，**最终角色美术、动画资产、3D 与声音升级仍待用户选方向**。

## 判断与建议

优先学习 **Bongo Cat 的输入因果、Incredibox 的角色表演、Chrome Music Lab Rhythm 的乐器动作、Patatap 的即时触发**，而不是把它们的界面拼成一个音乐 App。角色必须让人一眼看懂“我的这一按，让它做了这一下”。小猫可以可爱，但画面里必须发生可辨认的演奏动作。

短期建议保留分层 SVG 作为可交互原型；最终美术优先比较两条小样：

1. **原创猫插画 → 分层 PNG / 短 sprite → 前端状态机。** 猫身体、头、左右爪、眼睛、嘴、乐器分开，按下出爪、触底压缩、松开回弹。适合保留 GPT 生图的质感，同时真正响应输入。
2. **预渲染 3D 质感 → 有限方向图/短视频帧 + 独立演奏层。** 适合用户提供的追光猫参考。先验证“看向鼠标”和“按键出爪”可以并行，不能把整段成片当交互角色。

只有这两条仍无法达到用户期待的空间转身、实时灯光和接触阴影时，再考虑 Three.js 真 3D。Rive 是有持续动画设计需求时的备选；Spine 不是这一轮的默认依赖。最终方向的选择不等于已批准批量制作素材。

## 证据范围与已知缺口

- 本轮打开并读取以下官方作品页、GitHub README/源码与许可证；Bongo Cat 另在独立 Chrome 标签实际打开，观察画面、键位和署名，并发送了一次 A 键。未录制其音频，未由此声称完成听感、延迟或手机验收。
- 本轮旧 Demo 源码：`MiaoTI仓库的 experiments/keyboard-cat/`。它使用自行绘制 SVG 与 Web Audio 合成音，左右爪主要是 12px 平移和旋转。是否“像演奏”不能靠出现 class 或动画 API 来证明。
- GitHub 无认证 API 返回 403 rate limit；没有据此编造最后提交日期。表中“站点可访问”与“代码有人维护”严格区分。许可证 unknown 的候选仅作体验参考。
- Chrome Music Lab 的文本抓取会返回兼容提示，不能用它证明实验运行成功。Sampulator 当前返回的页面只有简短占位文字，已降级为历史候选，不能继续推荐成已验收可玩的现成产品。

## 用户提供的追光猫参考：已看到什么、还不知道什么

用户提供笔记标题片段：“用AI做一只3D可交互的追光小猫～ 网上刷到了小猫交互...”。[原分享链接](https://xhslink.cn/o/8oQtxWNLGCT)，[去掉临时验证参数的笔记地址](https://www.xiaohongshu.com/explore/6a95807e0000000020031552)。不保存重定向中的 `xsec_token`。

同轮主 Agent 在真实浏览器打开笔记并看到视频播放，视频时长显示约 78.6 秒；作者“陈小爷”，页面日期显示“08-31”，**没有显示年份**。画面是黄背景、毛绒黑猫和大黄眼，小红点与电脑屏上的猫视线交互。作者文案讲的是选择猫图、在视频生成网站生成各方向的视频、交给 AI agent 制作；没有披露具体视频网站、完整代码或资产许可。这些事实来自主 Agent 的可见页面观察，本子任务没有独立观看整段视频或获取源码。

因此只能判断它很可能采用**预生成方向视频/帧来组织交互**，不能宣称它是 Three.js、可自由旋转的骨骼模型，或已证明任何方向、任意动作都能实时衔接。标题里的“3D”首先可能指渲染质感，不等于交付了三维网格、骨骼和实时灯光。许可未核实前只参考机制，不复制该猫图/视频。

可借鉴的是“小猫在看我的操作”，不必限定为追光猫复刻。对本站更有用的组合是：闲置时看向指针，弹左侧音区向左关注、右侧向右关注，敲鼓明确出爪；声音、手和身体反应统一。鼠标跟随不能压过演奏优先级。

## 动画技术路线比较

以下体量/耗时判断是本项目工程判断，不是对上游的实测性能数据；首包大小最终要读构建产物，不能拿格式名推导“零成本”。

| 路线 | 能否响应按下/松开、连续输入 | 对 GPT 生图的实际要求 | 首包、制作与维护 | 本项目判断 |
|---|---|---|---|---|
| 分层 SVG + CSS / Web Animations API | 很好；左右爪独立，取消/替换动画可控，按住姿态可分离 | 生图只能做参考；不是“PNG 自动变成干净 SVG 骨骼” | 几个 SVG group，无运行时依赖；效果取决于造型与动作设计，不能只做整体平移 | **本轮 UI 临时路线**，先验证动作因果 |
| GPT 插画 → 分层 PNG/WebP + CSS/WAAPI | 很好；位移/旋转/局部 squash、眼嘴状态都可独立 | 需要同角色中立姿、分层、遮挡后的补全、固定锚点；头/两爪/乐器/背景分离。生成一张漂亮图不等于可动资产 | 少量透明贴图即可；工程轻，分层品质是主要工作。旋转过大会露缺口 | **最终美术优先小样 A** |
| Sprite sheet / 多状态小图 + Canvas | 可以；引擎明确跳到攻击、触底、释放帧，重击可打断 | 同一大小、同一机位、同角色比例、脚/乐器不漂；中间帧需检查，不能直接信任生成拼图 | 固定帧数导致内存/包量增长；一只猫用原生 Canvas 即可，角色/粒子多后再考虑 Pixi | **优先小样 A 的备选载体**，尤其适合有手绘变化的爪子 |
| GIF / 循环动图 | 弱；`img`没有可靠的任意帧 seek、独立部位控制和精确释放接口 | 可以快速得到预览，但单段动画包含所有动作，连续按键容易反复重启或不能重启 | 成品易看，交互层却难；GIF 解码体量也未必比视频低 | 仅用于分享预览/闲置装饰，**不做核心击键反馈** |
| 方向视频 / 预渲染“3D”片段 | 中；有限方向可播/切帧，打断与跨动作组合要另设计 | 必须固定机位/角色/光照，预备中立、左/右/上/下看、按爪和恢复；整段生成视频不等于每帧可任意连接 | 有解码/切片/首帧准备成本，方向越多越重；看向与出爪分层能避免动作组合爆炸 | **最终小样 B**；先 5–9 个看向状态，演奏层独立 |
| Lottie / dotLottie | 可以控制片段和帧；本质仍是时间轴，需要自行组织输入状态 | GPT PNG 不能直接成为高质量可编辑 Lottie；要矢量描绘/AE 或兼容动画制作流程 | [lottie-web](https://github.com/airbnb/lottie-web) MIT，支持 `goToAndStop` / `playSegments`；多 mask/path 会加重，JSON 与图片资产另外核权。维护精确日期本轮未核实 | 已有成熟 AE/Lottie 动画才优先；**不为两只爪子引入整套流程** |
| Rive | 好；状态机/数据输入适合按下、按住、松开及视线混合 | 需要在编辑器建立分层、骨骼/约束与状态机；不是 GPT 图自动转换 `.riv` | [Web runtime](https://github.com/rive-app/rive-wasm) 为 JS/WASM、MIT；[发布页](https://github.com/rive-app/rive-wasm/releases) 可见 2.45.0 / 10-17 更新。编辑器方案与资产许可另算，不能由 runtime MIT 推断素材免费 | 以后需要持续做多角色复杂动画时选，当前**备选** |
| Spine | 很好；骨骼/混合/事件支持角色表演 | 需要切图、补遮挡、rig 和 authored animation；能管理复杂动作，但需要专业制作 | [Runtime](https://esotericsoftware.com/spine-runtimes-license) 是自定义授权，不是 MIT；正常集成需满足 Editor License 等条件。编辑器与素材成本均需明确 | **本轮不引入**，收益不足以覆盖流程成本 |
| 真 3D：Three.js + glTF 骨骼/形态键 | 最强；真实转头/看向目标、独立爪子、光源与遮挡 | GPT 图仅是概念；仍需网格、拓扑、材质、骨骼权重、动作和减面。单张生图或一段视频不是 glTF | [Three.js](https://threejs.org/)当前官网标 r186，[runtime MIT](https://github.com/mrdoob/three.js/blob/dev/LICENSE)；模型/纹理/HDRI/动画分别许可。带来 renderer、模型、纹理、GPU与移动功耗成本 | 只有需要**真实空间与灯光**时再选，不为“看起来像3D”直接升级 |

[WAAPI](https://developer.mozilla.org/en-US/docs/Web/API/Web_Animations_API/Using_the_Web_Animations_API) 能暂停、取消和调整播放，因此比靠增删相同 class 重启长动画更适合可打断反馈。Canvas/Pixi 也不会自动解决时钟或多指状态；[Pixi MIT](https://github.com/pixijs/pixijs/blob/dev/LICENSE) 只覆盖引擎，不覆盖素材。

## 先把“按下—触底—回弹”定义清楚

建议的角色输入状态（设计目标，不宣称原型已经完整具备）：

| 输入 | 角色反馈 | 中断与释放规则 |
|---|---|---|
| 第一次 note-on / pointerdown | 对应爪抬起后快速触底；琴键压低，局部触点可见 | 声音直接触发，不等待 100ms 的抬手预备动作；视觉预备仅用很短的过渡 |
| 同键继续按住 | 键保持按下，爪可以留在触底姿态 | 本轮音源是 one-shot，不能宣称键长决定音长；未来 sustain 需额外 note-off 音频接口 |
| 松开 | 爪和琴键回弹，眼/耳可给一次轻跟随 | 不截断其他仍按住的键；左右爪分别管理 |
| 快速重敲 | 从当前视觉位置进入下一次接触，短反馈重触发 | 不把整个 500ms 动画排队，否则角色会落后演奏 |
| 左右同时按 | 两爪都动作，身体只给小幅反作用 | 不让单个 `lastPaw` 覆盖另一只爪；键盘、鼠标和多指来源分开记状态 |
| 节拍器击拍 | 头或耳轻点一下，第一拍有不同提示 | 不代替键触发的出爪，不和按键争夺同一 transform；关闭即停止下一拍动作 |
| 指针/追光 | 眼/头跟随一个小角度/有限方向 | 演奏优先，视线偏移受限；手机没有 hover，不靠模拟鼠标来回移动 |
| blur / visibilitychange / pointercancel | 清空 pressed 状态、回到中立 | 防止切后台/来电/手指滑走后永远压着琴键 |

数字目标作为第一轮验收线：视觉响应在下一至两帧出现；触底约 40–70ms、回弹约 120–200ms。它们是建议参数，需要浏览器录像/性能记录与真实手感调校，不是行业标准或当前已测结果。减少运动模式仍保留按下状态、拍点和可读状态，不用大幅抖动或全屏闪白表达节拍。

声音调度应以音频时钟为主；rAF 只负责根据该时钟显示当前画面。节拍器不能用 CSS 无限循环假装与声音一致，也不让 `setInterval` 累加成为唯一节拍依据。可用 [AudioContext.getOutputTimestamp](https://developer.mozilla.org/en-US/docs/Web/API/AudioContext/getOutputTimestamp) 在支持的设备上关联音频/性能时钟，但它不消除蓝牙硬件延迟；真实听感和扬声器输出仍须实测。

## 键位、谱子与手机

- 电脑采用钢琴式自然布局：白键 `A S D F G H J K` 对应 `C4 D4 E4 F4 G4 A4 B4 C5`；黑键 `W E T Y U` 对应 `C#4 D#4 F#4 G#4 A#4`。键帽主层写物理键，次层写音名，避免 Do/Re 与字母键、简谱数字混为一谈。`KeyboardEvent.code` 按物理位置映射，输入框、select、快捷键组合获得焦点时不抢按键。
- 打击乐 `Z X C V` 固定四种声音即可；不要为了“完整键盘”把 26 个音色塞进首屏。音符/鼓的现场状态清楚比声部数量更重要。
- 参考谱默认折叠，每句一个视觉组，显示简谱音符 + 键位 + 时值，必要时标高音点/降号。生日快乐需明确 3/4 拍；它需要的降七音键 `U` 标作 `♭7 / U`，不能当正常高八度。曲谱参考与示范播放器共用数据，避免显示对但试听错。
- 本轮粉刷匠只做明确标注的开头两小节，不借社区配谱/现代录音。Bongo README 的歌曲键序证明极简提示有效，**不等于把该社区曲谱/录音许可转授本项目**。
- [Pointer Events](https://developer.mozilla.org/en-US/docs/Web/API/Pointer_events) 统一触屏与鼠标；用 pointerId 管理多指、pointer capture 保证离开键帽仍收到释放，同时处理 cancel/lost capture。只在演奏区域禁止滚动手势，不让整页失去滚动和缩放。
- 手机保持自由演奏：猫与节拍器缩小，旋律键和四个鼓垫可尽早操作。黑键在窄屏会比理想触控目标更窄，不能谎称13个完整琴键在320px都满足44px宽；若实测误触高，采用自然音主视图＋可展开半音垫/横向琴键区，先保住常用曲子的可玩性。
- 双指和弦、手指从键上拖走、来电/切后台后恢复、静音/AudioContext暂停、首次点击解锁声音都必须独立检查。桌面设置390px视口只证明排版，不证明真手机扬声器、多点触控与音频延迟。

## 轻量片段记录的边界

用户已允许记录时间与键位、导出用户自存并导入回放。建议保留为演奏控件下的小条：开始/结束、回放、导出JSON、导入，不加项目管理器。记录按键触发事件而非音频，不申请麦克风。元数据固定音色版本/映射版本、BPM和拍号；明确现阶段只重现 one-shot 触发，不承诺还原按住时长、声音文件、外接 MIDI 或未来更换采样后的同一音质。

录制不应偷偷量化到拍点；用户自由节奏也是作品。回放按同一事件流驱动声音和猫，结束/停止必须清理调度。导入只接收受限JSON数据，检查时长、事件数、键值与时间排序，不执行代码，不联网拉取用户指定脚本/音色。

## 分阶段验收与停止条件

| 阶段 | 最便宜的可证伪测试 | 通过才做下一步 | 停止/换路线条件 |
|---|---|---|---|
| 当前 UI 原型 | 一只猫、13音键、4鼓、节拍器；用户自由按、松、同时按，谱子默认折叠 | 每次触发有对应声音和清晰局部动作；按键可恢复，所有操作不被动画阻塞；3/4与4/4拍点一致 | 画面依然只像图标轻移，先修动作；声音仍难听时不要用大量动画掩盖音源问题 |
| 素材小样 A | 只做一只猫中立/左击/右击/双击/看向，最多一页资产清单 | 角色一致、爪与乐器接触点稳定；8Hz短敲和左右并发不积压；静置无持续高成本渲染 | 遮挡补全反复失败、机位漂、爪子每帧变形：停止扩图，改分层/减少状态，不继续批量生成 |
| 预渲染小样 B | 同一只猫的少量看向状态，与独立出爪层合成 | 快速左右移动指针不会闪回/跳脸；演奏能打断注视；手机无hover也能自然玩 | 必须等待完整视频结束、方向切换明显跳变、完整首包过大：退回分层图，不添加更多方向“补洞” |
| 真实手机 | iPhone Safari + 一台Android Chrome；先开声音，再双指、切后台、开拍2分钟 | 无卡键；拍子不逐渐漂；关掉节拍器确实停止；320/390/768px无横向溢出且主要控件可达 | 黑键误触/首包等待明显、设备发热/掉帧持续：先减资源和画面复杂度，不加复杂骨骼栈 |
| 决定是否上真3D | 比较同猫同动作的2.5D与低模3D小样，不同时改音源/UI | 用户明确需要实时视差/灯光/空间转向，且低端手机开场成本可接受 | 只为“看起来高级”但交互没有改善，就不进入建模、rig、多材质和复杂后处理 |

建议首轮预算：角色动画资产增量先控制在约 1MB 压缩传输内，主要页面不为追光效果强制下载大视频；如果路线需要几倍于此的首包，先拿两台真实手机对比再决定。此数字是可调整的工程预算，不是已经测得的包体。

最终提请用户确认的是“分层插画/短sprite，还是预渲染3D质感猫”，以及希望的猫造型和表演强度；无需让用户先选 CSS/Canvas 这种内部实现名词。新 UI 与临时 SVG 的可玩交付，不代表最终美术路线已经被确认。
