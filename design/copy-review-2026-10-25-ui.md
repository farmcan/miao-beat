# Miao Beat 文案审查：少说两句，让人先弹

2026-10-25。读取当前 `public/index.html` 全文，并核对 `app.js`、`performance.js`、`full-frame-character.js` 中实际覆盖页面的动态提示。当前生产基线为 0.10，source `379a2ae`、Cloudflare `67f63e27`（由主线程提供）；本审查没有修改运行代码或部署。

建议先用一套口吻做小范围替换，再看用户反应。下面的中文是原创提案，不是已流行的网络梗，也没有“已验证提升留存”的结论。

## 核心判断

现在的问题主要是重复营造气氛，而不是“不够有梗”。首页同时出现：

> 随手一弹，猫就来劲。／给今天配点声音。／你来弹，猫来演。／自由发挥，不用打分。／第一声，交给你。／猫的现场。

下面又有“给灵感打个拍子”“没有‘弹错了’，只是这一小段，刚好长这样”“猫猫还有别的拿手戏”“换个心情，再玩一个”。单独一句未必有问题，但连起来像在反复解释这个玩具很放松、很温柔。用户还没按第一下，就先看了好几层态度。

“听一遍”“跟着弹”“低音／高音”“慢一点／快一点”其实已经很自然，可以保留。版权、文件格式、计数口径与付款说明是事实信息，不应为了口语化删掉。

## 实际查到的参考

| 来源 | 观察到什么 | 可以借什么，不能借什么 |
|---|---|---|
| [Bongo Cat 原站](https://bongo.cat/)（2026-10-25 读取） | 主要是乐器名称和键位，如 Bongos A D、Meow SPACE；角色本身承担趣味 | 让操作标签靠近操作物，减少解释角色“有多可爱”的话。它不是中文口吻证据，也不能仅凭文案短就断言转化更好。 |
| [Patatap 原站](https://patatap.com/)（同日读取） | 用一段很短的说明把触碰与声音/图形反馈联系起来 | 首页只交代一种直接因果。不要把它的英文宣传句逐字翻译成另一句中文品牌宣言。 |
| [极目新闻：电子木鱼报道](https://www.ctdsb.net/c1476_202212/1589494.html)（2022-12-05 原始报道） | 记录了敲击与“功德+1”的即时反馈，也记载用户自定义短文案 | 真正有用的是“一次动作对应一个可理解反馈”。这是 2022 年特定文化语境的历史案例，不能说成 2026 年新热梗；报道里的规模/解压说法也不是 Miao Beat 的效果证据。 |

本轮不建议把“功德+1／赛博功德”放进主标题，也不造“喵力+1”“烦恼-1”再称其为热点。钢琴输入不需要另一套计分暗示，产品也没有心理效果证据。笑点可以来自猫正在做的事，不必另外让用户理解一个梗。

## 三个短方向

| 方向 | 主标题 | 副文案示例 | 判断 |
|---|---|---|---|
| A：随口招呼 | **来，弹两下。** | 先打开声音，再点下面的琴键。 | 首选。短、具体，不先要求用户认同“治愈”“自由”或懂梗。 |
| B：猫是同桌 | **猫在，随便弹。** | 点琴键，或者用电脑键盘。 | 猫的存在感更强，但后面若继续加“陪伴／接住／不嫌弃”，很容易又写成安慰文。 |
| C：稍微有点动静 | **先来点动静。** | 弹琴、扫和弦，也能敲鼓。 | 有一点玩心，适合节奏玩具；初次默认钢琴时，信息比 A 稍散。 |

不建议三套混搭。推荐 A 做整页基准，猫的表情和动作已经足够承担角色感。

## 推荐整套：A

### 首屏：一句招呼，一句操作

| 位置 / 当前文案 | 建议 |
|---|---|
| 主标题“随手一弹，猫就来劲。” | **来，弹两下。** |
| 桌面副文案“按个键，给今天配点声音。不会乐器，也能玩。” | **先打开声音，再按 A S D F，或者点琴键。** |
| 手机副文案 | **先打开声音，再点下面的琴键。** |
| A LITTLE MUSIC, A LITTLE MIAO | 建议删掉；品牌标识保留 MIAO / BEAT。 |
| “你来弹，猫来演。”／“自由发挥，不用打分。” | 两句都不必另放在舞台上方。退出演奏等功能入口仍保留。 |
| “第一声，交给你” | **点个键试试**；开始后直接显示现有音名/鼓名。 |
| “猫的现场” | 可直接不显示文字，不另补一句口号。 |
| 乐器选项 | **钢琴／马林巴／尼龙弦吉他／架子鼓**。保留真实乐器名，去掉“清亮琴房／木头叮咚”之类第二层包装。 |
| 顶部“开始演奏” | **去弹琴**。也可保持原词，优先级低于首屏重复句。 |

手机不应只给“A—K”作为第一步：手机用户手里没有字母键盘。电脑键位放在对应琴键上，桌面再补一行；手机第一步用“点”。“不会乐器”不是必须先解释的问题，用户可以直接试。

### 第一下：把加载讲明白，不拿气氛句遮住状态

| 状态 | 按钮 / 提示 |
|---|---|
| 尚未准备 | 按钮 **打开声音**；手机 **先打开声音，再点琴键。**；桌面 **先打开声音，再按 A 试试。** |
| 加载中 | 按钮 **加载中…**；提示 **第一次要加载声音，等好了再点一下。** 如展示进度，写“正在加载声音（8/13）”，不必说“真实采样”。 |
| 冷启动时用户先点了键 | **声音还在加载，等好了再点一下。** 保留“需重新按”的真实语义，不补播陈旧输入。 |
| 加载完成 | 按钮 **可以弹了**；提示 **点琴键试试。** 桌面可用“按 A 试试。” |
| 已正常弹出一音 | 保留音名/鼓名即可；不再每次切换“开始你的节奏／继续你的旋律／打开节拍器或者按感觉弹”等整句。 |
| 加载失败 | 按钮 **重试**；提示 **声音没加载出来，点“重试”。** |
| 已准备但用户听不到 | 辅助提示可用 **还是没声音？看看音量和设备静音。** 放在失败/帮助处，不在每次进入都讲。 |
| 单次播放失败 | **这一下没响，试试重新打开声音。** |

不要把“音色加载失败”与“设备静音”混成同一个原因：静音一般不会导致网络音色加载失败。也不要承诺“马上／一秒／等三秒”，当前没有统一网络时长保证。

### 演奏区：直接叫它的名字

| 当前位置 | 建议 |
|---|---|
| “你的琴键” | **琴键** |
| 手机“点按琴键，也可以一起按” | **点着弹，也可以一起按。** |
| 低音 / 高音 | 保留。中间“切换琴键”可以省掉，按钮已经说明动作。 |
| 手机横滚提示 | **右边还有琴键，点“高音”往右看。** 只在确实溢出时出现；不在能看全的横屏重复提示。 |
| “先扫一个和弦” | **扫个和弦** |
| 手机和弦说明 | **点 C → Am → F → G，每个和弦弹四拍。** 电脑另写“按 1—4”。 |
| “添点节奏” | **鼓垫** |
| “给灵感打个拍子” | **节拍器** |
| 开节拍 / 停节拍 | **开节拍／关节拍**；也可保留“停节拍”，不必全改。 |
| “点按测速” | **跟着点几下**；辅助说明 **按你的节奏点，会自动调速度。** |
| “第一个小节，可以这样玩” | **试试这个节奏** |
| 手机鼓说明 | **闭镲点八下。第 1、3 拍加底鼓，第 2、4 拍加军鼓。** “先调到 80 BPM”留在第一句；字母键只在电脑说明。 |

### 曲谱与跟弹：不把“不判分”到处重复

| 位置 | 建议 |
|---|---|
| 口袋谱 | **曲谱** |
| 跟着弹 / 听一遍 / 停止 | 保留，这三项已经很清楚。 |
| 初始提示 | **选一首，先听一遍，再跟着亮起的键弹。** |
| 预备拍 | **准备，数四拍。** 弱起曲仍按真实两拍等显示，不能把四拍写死。 |
| 当前音 / 下一音 | 保留实际音符；手机优先显示音名/简谱数字，字母键作为电脑对应信息。 |
| 跟弹运行 | **只放节拍，旋律你来弹。** “不判分”只在帮助里说一次。 |
| 示范运行 | **正在示范。想自己弹，直接点琴键。** |
| 跟弹结束 | **这一遍弹完了。再来一遍？** |
| 示范结束 | **听完了，换你试试。** |
| 手动停止 | **已停止。** |
| 修改速度后 | **速度改了，点“跟着弹”重新开始。** 若改的是拍号，应使用“拍号改了”，不要说错原因。 |
| 原来的三段式参考册入口 | 主文 **看谱弹**；辅助文 **字母是电脑按键，数字是音符。**；展开动作 **看琴谱**。避免“从哪一音开始／打开参考册／展开完整键位”三次表达同一动作。 |

建议“每段下一步”只说一次。原谱来源与简化/改编范围按现有真实内容保留，不让有趣文案覆盖来源信息。

### 记录、空状态与文件

| 状态 / 位置 | 建议 |
|---|---|
| 开始 / 结束记录按钮 | **开始记录／停止记录**。不用“录音”，功能保存的是按键事件。 |
| 尚无片段的说明 | **想留一段？点“开始记录”，再弹。** |
| 记录中 | **记录中 · 最长 5 分钟。** 辅助文 **只记你按的键，节拍声不记入。** |
| 正常结束 | **记下了，点“回放”听听。** |
| 空记录结束 | **没记到按键，再试一次。** 不用“弹错／失败”评价用户。 |
| 回放按钮 | 保留 **回放**；运行中 **停止回放**。 |
| 回放提示 | **正在回放。想接着弹，直接点琴键。** |
| 保存演奏文件 | **保存片段**；旁边说明 **保存的是按键和时间，可导入这里回放。文件不上传。** |
| 导入片段 | 保留。 |
| 文件生成成功 | **演奏文件已生成，下载后可以再导入回放。** 当前只调用浏览器下载，没有完成落盘回执，不能保证“已经存好了”。 |
| 读入成功 | **打开了，点“回放”就能听。** |
| 文件格式不符 | **这个文件打不开，请选本站保存的演奏文件。** 展开的详细错误仍保留，不必把全部技术信息塞进按钮。 |
| JSON 复制区 | 标题 **复制演奏文件内容**；说明 **下载不方便时，可以复制这些内容，存成 .json 文件。** 仅需保存/排错时展开，不当主流程。 |

保留“按键与时间”的事实，不宣传成可直接发给朋友播放的音频文件。当前没有生成分享音频的闭环，不能仅靠一句文案假装已经支持。

| 页脚英文标语 | 可删 MADE FOR A LITTLE JOY，保留品牌即可。 |

| 版权/素材来源 | 保留来源、许可、原谱入口和无麦克风/上传等真实说明，不为了短而去掉。 |

## 先试哪一小版

先替换主标题、副文案、声音准备状态、五个区域标题、记录结果和页尾气氛段。不要同时加飘字、热梗计数或新的角色对白。手机第一屏只需回答：这是什么、先点哪里、声音没出来时要不要再按。

验证时请第一次来的用户在手机上打开：能否不听解释就找到声音入口；加载后是否知道要重新点键；能否区分“听一遍”和“跟着弹”；是否误把保存片段理解成音频。这里是待验证的问题，不是完成证据。

文案自然不自然仍由用户判断。推荐稿减少了重复抒情和拟人句，但不能把“更短”直接等同于“更好玩”。
