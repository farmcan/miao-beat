### P2：首次切换未缓存乐器期间舞台空白

`full-frame-character.js` 的 `update()` / `strike()` 换 mode 时隐藏 canvas，却没有重新显示加载文字。上次成功帧的 message 是 `hidden=true`、空字符串。新乐器 idle 尚未载入时，用户只能看到空舞台，声音可能已就绪。

使用 JSDOM 模拟已加载钢琴，延迟 `guitar/idle.jpg` 请求，再 `update('guitar', [])`，实际得到：

```json
{"canvasHidden":true,"messageHidden":true,"messageText":"","status":"loading"}
```

最小修法：每次更换 mode 后立刻让 message 显示“猫的图还在加载…”，成功帧再收起；失败继续保留当前明确的“声音还能用”。不应回退分离角色。

**后续修复记录（root 回报）**：root 已修改 `update` / `strike`，更换 mode 时立即显示加载消息并隐藏旧 canvas，并给延迟旧 guitar 请求测试加断言，报告通过。本独立审查没有重复修改代码；生产和实际浏览器验收由 root 继续，不以这条回报替代线上证明。

root 还回报已在 390×844 发现并修正 resize 后桌面 ASDF 提示残留：媒体条件变化只刷新 idle/ready/running 提示，加载和错误不被覆盖。鼠标/触摸选乐器后将焦点移至 `playingSurface`，键盘选择则保留原生 select 焦点。这两项为 root 实测/实施的记录，本报告未独立重复验收。

### 待浏览器验证，不能当成已发生故障

- 冷网络下很短的按键可能在图片完成前已经到期。丢掉陈旧姿态比补演奏正确，但第一次声音与姿态能否同拍仍需真实浏览器/节流验收。
- 第一张钢琴 idle 加载失败会让 `loaded=false`，其它乐器也不启动；当前有明确文字降级，尚未核验是否要提供重新载图入口。
- 切帧的轻微光照变化、手机上的细小把位差别、用户对猫爪的审美接受度不由代码/逐图检查替代。
